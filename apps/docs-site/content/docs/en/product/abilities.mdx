The **Capabilities** page at `/abilities` is the extension entry point. It adds skills, MCP connectors, plugins, and capability bundles to an Agent.

## Capability types

| Type | Purpose |
| --- | --- |
| Skill | Task instructions and workflow prompts |
| MCP | A connection to external tools and data |
| Plugin | An extension to the desktop UI and Agent capabilities |
| Bundle | Several capabilities organized as one installable selection |

## Choose by goal

| Goal | Prefer | Why |
| --- | --- | --- |
| Make the Agent follow a stable method | Skill | Guides one task with instructions and a workflow |
| Call an external service or data source | MCP | Provides a structured tool connection |
| Extend the desktop UI, files, or messages | Plugin | Enters the host UI and Agent lifecycle |
| Install coordinated capabilities together | Bundle | Provides one discovery and selection flow |

If you only need an external API, do not start with a desktop plugin. If you only need a stable prompt workflow, you do not need an MCP server.

## Discover and manage installed items

- **Discover** browses capabilities that can be added, including recommended connector groups.
- **My capabilities** manages installed items: enable, disable, configure, update, and remove.

Search by capability name. Cards show the source, version, and state, such as needs configuration, update available, or enabled.

## Search the MCP discovery catalog

Under **Discover**, the **MCP discovery catalog** lists unreviewed public candidates separately from installable capabilities. Combine category, functional tag, runtime mode, platform, permission scope, authentication, and publisher filters. Missing information is shown as **Unknown**, which does not imply that no permissions or authentication are required.

Keyword searches progressively scan names, summaries, and their English and Chinese text, including pages that have not been loaded yet. Results and progress appear while scanning; the final count is shown only after completion. Each source displays a window of 60 results with previous and next controls. Full details load when opened; text beyond the summary is outside keyword search coverage.

- **Pause and retry:** Pause a scan while retaining its displayed results. Retry reuses validated cache entries and downloads missing content. Results remain partial when any part fails.
- **Change filters:** Changing the keyword or filters cancels the previous search so late results cannot enter the new query.
- **Refresh:** Each search uses one fixed catalog revision. Refresh selects the new revision without mixing pages from different versions.
- **Read-only candidates:** View descriptions, sources, and documentation without installing from the discovery catalog. Classification and permission metadata are not security approval. Skills and reviewed MCP connectors retain their existing installation flow.
- **Offline and older catalogs:** Validated cache entries remain available. Uncached pages are unavailable offline and are reported as partial failures. Sources that have not deployed v2 use the existing protocol. If the compatibility catalog is marked frozen, older clients see its previous snapshot while this client uses the complete v2 catalog.

Each source uses bounded download concurrency and an approximately 200 MiB cache budget. Least recently used shards are evicted when necessary. This budget does not limit total v2 catalog size or affect installed capabilities and user configuration.

## Add from the marketplace or list

<Steps>
  <Step>
    ### Open details

    Select a capability from the Discover list. The drawer shows its description, source, version, and permissions.
  </Step>
  <Step>
    ### Add it

    Select **Add capability**. A bundle lets you choose its members; already-installed members that need no update are not installed twice.
  </Step>
  <Step>
    ### Complete configuration

    MCP may require credentials or browser authorization. After a plugin is installed, confirm **Enable and permissions** and grant each required permission before use.
  </Step>
  <Step>
    ### Verify in a session

    Return to a session and confirm that the expected skill, tool, or plugin entry point is available.
  </Step>
</Steps>

## Add capability menu

Select **Add capability** to choose one of these sources:

| Method | Description |
| --- | --- |
| Import skill archive | Local `zip`, `tar.gz`, or `tgz` |
| Import plugin archive | Local ZIP with `plugin.json` at its root |
| Add external repository | GitHub `owner/repo` containing `.vetta/marketplace.json`; it syncs immediately |
| Add MCP manually | Configure a STDIO or HTTP MCP server |

Import only trusted sources. If an external repository fails to sync, the app may retain its last usable content and show an error.

The 567 Agent official source (`Chinachani/567-agent-marketplace`) ships with the app as a built-in source: it is always enabled and cannot be disabled or removed. Sources you add yourself can be disabled or removed at any time.

## Management and troubleshooting

- **Disable** keeps the installation but stops using it.
- **Remove** uninstalls the local capability.
- **Update / reload** is for new versions and development debugging.
- If another source already owns the same capability ID, 567 Agent does not overwrite it automatically; confirm the source in the details view.
- MCP is written to `~/.567agent/agent/mcp.json`; skills and plugins are stored under `~/.567agent/skills` and `~/.567agent/plugins`. The installation index is `~/.567agent/abilities.json`.

For plugin development, read [Plugin development](/plugins/overview/). For an external tool service, read [MCP connectors](/product/mcp/).
