# 模型上下文容量

电脑端在“设置 → 模型配置 → 上下文容量”默认定位当前模型，可搜索并选择“模型 · 服务商”，输入容量后保存。支持完整整数、千分位以及 K / M / Ki / Mi，常用容量按钮只填入草稿，点击保存才生效。K / M 按 1,000 / 1,000,000 计算，Ki / Mi 按 1,024 / 1,048,576 计算；界面显示解析后的精确 token 数。切换模型保留本页尚未保存的容量草稿。这里包含自动接入的 567 分组。设置会影响该模型后续任务的压缩预算，正在执行的任务继续使用原参数。留空或点击“恢复自动识别”可移除覆盖值。

手机直接调用 API 时，在会话的“上下文管理”填写容量；新对话发送消息前也能设置。容量按服务器、分组、模型保存，刷新模型列表或重启后保留。手机远程电脑会话只查看电脑容量和来源，修改须在电脑进行。

手机接口元数据最多缓存 12 小时，过期后刷新模型列表可重新读取；手动设置不会过期。

来源顺序为：手动设置、服务商接口明确返回的容量、公开参考资料。两端共享更新后的 models.dev 容量表，以及逐项核对的官方资料和显式代理别名对照。界面会显示来源；目录容量只是参考，后端代理可能另设较低限制。已列入对照的代理别名会显示参考的上游型号及提醒；例如 gemini-3.8-flash-high 参考 gemini-3.8-flash，而不是宣称网关已确认该容量。未列入对照的别名继续显示未知，不按模型族名称猜测。资料来源和核对日期可查看。

手机自动压缩在已知容量时生效，约 80% 触发，并预留回复空间。优先保留最近三轮，空间不足时保留最近一轮；压缩后仍超过预算会保留草稿并提示减少输入、核对容量或开始新上下文。容量未知时可手动填写，也可以手动压缩。估算不是精确分词计量，设置容量也不会扩大服务商实际限制。

旧电脑版本生成的默认容量可能只是运行保护预算。升级后这类值标为未知；有已核对参考资料的型号会在读取旧配置和启动运行时阶段获得参考容量；接口后续返回明确参数时仍以接口为准。可以直接手动覆盖。

历史自定义模型在配置文件里明确填写的容量仍有效；“恢复自动识别”移除本轮新增的覆盖值。

## 服务端如何提供容量

优先在当前用户有权访问的模型列表中提供明确字段，如 `context_window`、`context_length` 或 `max_input_tokens`，并另行提供输出上限 `max_output_tokens`。Gemini 原生接口使用 `inputTokenLimit` / `outputTokenLimit`；只返回模型名称的接口无法让客户端准确获知容量。不要把输出长度或账户额度作为上下文容量。

如果以后使用 LiteLLM，可由后端把模型能力转换到只读的用户模型列表，按当前用户、分组和路由返回实际有效限制。客户端不需要也不应保存 LiteLLM master key；本轮未新增对管理接口的自动访问。模型重命名时由后端明确提供对应能力，优于客户端猜测别名。

## 兜底数据维护

2026-10-15 联网采集：22 个目录来源加文心官方资料，共 408 条型号/别名记录，其中 381 条有容量参考，27 条容量未知。完整逐项对照见 [模型容量采集记录](model-context-reference-research.md)。这些数据覆盖 23 个模型来源和当前接入/旧缓存的型号，不代表已经遍历 567 API 所有未接入分组。

- 单一审核源：apps/desktop/src/shared/model-context-references.json。
- 在线目录快照：apps/desktop/src/shared/model-context-catalog.generated.json。
- 联网更新：仓库根运行 `bun run --cwd apps/desktop snapshot:models-dev`。
- 修改审核资料后重新生成手机表：`bun run --cwd apps/desktop snapshot:models-dev --from-bundled`。
- 生成的 Kotlin 和桌面快照不应手工修改。

图像模型没有公开聊天 token 上限时保留未知，不能把图片分辨率、每分钟张数或最大输出 token 当成聊天上下文容量。

## 模型能力与参数资料

电脑容量设置展开“查看模型能力与参数”、手机上下文管理展开参考资料，可查看最大输入、输入输出类型、工具调用、思考控制/档位、温度与 Top-P 支持情况及已核实的范围。字段缺失时显示未知，不视作不支持。资料、参数限制文档分别提供来源链接；对具有思考模式限制的采样参数会说明适用条件。

能力与采样参考只读，实际请求继续由现有模型适配器处理。修改容量会进入压缩预算；不会根据公开资料自动改写温度、Top-P、思考档位或工具请求。私有别名、图像等没有聊天容量的型号可以继续显示未知。
