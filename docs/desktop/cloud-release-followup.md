# 云端跟进 1.3.x 补丁

本轮云端执行器可通过 GitHub connector 提交并更新分支，但不必持有用户本机的 Git 凭据，也不必直接拥有打标签工具。

仅在本轮发布出现必须修改源码的问题时，修复并检查后提交到 main，同时更新桌面/Android版本、Android版本码和新版本发布说明。版本必须为尚未发布的 1.3.x 补丁，Android版本码为 `10300 + patch`。保留原标签及正式发布。

拿到最终代码提交的完整SHA后，再通过 GitHub connector 单独提交 `.github/cloud-release-request.json`：`enabled` 设为 `true`，`version` 为新补丁版本，`sha` 为已经包含在 main 中的该代码提交。请求提交本身不必成为发布提交。

`cloud-release-followup` 会核对提交属于 main、两端版本/Android版本码一致、发布说明非空，拒绝覆盖正式发布或移动已有标签。随后创建新标签并显式调度原 `desktop-release` 稳定发布流水线。完整测试、构建、安装验证、Release与更新源验证均继续由原流水线执行，不跳过门禁。

如果创建标签后调度失败，可重跑该入口；相同标签只能指向相同提交，已有在途或成功运行不会重复启动。原发布流水线失败时先读确切日志：纯基础设施问题可按原能力重跑，源码修复则使用后续新补丁，不能移动旧标签。

请求默认停用。维护者可手动运行该工作流的 `dry_run=true`，仅核对请求目标，不创建标签或发布。此入口仅覆盖本轮1.3.x；切换版本系列前另行审查。
