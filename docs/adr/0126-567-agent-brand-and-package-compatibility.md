# ADR-0126：567 Agent 更名与包兼容

- 状态：已接受
- 日期：2026-10-02

## 背景

仓库重建恢复了用户目录和 Android 身份迁移，但内部包名、界面文案、插件文件扩展名和
macOS 辅助程序实体仍有旧品牌。用户已同意统一品牌，新增 npm scope 并保留旧入口，
以及接受 macOS 辅助程序重新授权。需要把兼容决策和实现一起提交，避免重建再次遗漏。

## 决策

1. 未发布的内部 TypeScript 包使用 `@567agent/*`；Go module 使用本仓库完整路径。
2. 七个已发布的 `@vetta-org/*` 包保留为实现和运行时身份的事实源。在 `packages/npm-compat/`
   增加对应 `@567agent/*` 转发包，公开入口、CSS 和 CLI 由原 manifest 生成，依赖锁定相同
   实现版本。禁止复制 SDK 运行时形成第二份实例。
3. Module Federation 提供旧共享键和新名称，均指向相同宿主模块。`vetta-host:`、
   `window.vetta`、IPC、插件 ID、环境变量和持久化键保持兼容。
4. 插件构建和工作台导出使用 `.567plugin`，ZIP 容器与清单校验不变。系统双击和 CLI
   继续接受 `.vettapkg`；主动导入保留旧 `.zip`。npm 信封中的稳定归档路径
   `release/vetta-plugin.vettapkg` 保留，以兼容已发布分发合同。本决策取代 ADR-0121
   中关于默认用户文件扩展名的部分。
5. macOS 辅助程序使用 `567 Agent Computer Use.app` 和 `com.api567.agent.computer-use`。
   构建元数据、运行时定位和中英文提示同步修改。旧授权不能继承，需要重新授权。
6. CLI bin、Android applicationId、系统凭据服务 ID 保留。项目资源同时读取 `.567agent`
   和旧 `.vetta`，用户主目录使用 `.567agent`。
7. 上游版权和未决定的域名保留。新 scope 尚未执行 npm 发布，转发包发布前须先发布
   对应版本的实现包；源码增加入口不代表 registry 已经上线。

## 备选方案

- 直接重命名所有 npm 实现包：会改变已发布插件的共享键和依赖解析，需要重建生态。
- 同时打包两份 SDK：容易出现 React、上下文和插件注册状态分裂。
- 只改文案：不能解决辅助程序名实不符和包命名缺口。

## 验证

合同测试检查转发包的公开入口、CSS 字节一致、真实导出身份和 CLI 输出。插件包流程
覆盖新旧格式的构建、启动排队、确认、资源校验和版本目录安装。共享模块测试验证同一
宿主实例。完整类型和架构检查验证内部 scope，Go 全包测试和 vet 验证 module。
真实 macOS 授权和 Windows 文件关联仍需对应系统构建及设备验证补充。
