# 默认连接当前浏览器与新会话输入区组合

## 背景

1.4.0 的 Browser Use 指引默认新开独立浏览器，与用户期待操作桌面上已有的登录页面不一致。
用户选择默认优先连接当前浏览器，仅在明确指定时创建独立窗口。此次同时整理新会话页面，
将独立的模式、项目、智能体控件收拢至输入区，保留团队与第三方主题的既有能力。

## 决策

- Agent 的 CLI 指引先用 auto-connect 或用户提供的本地 CDP 端点发现标签页，明确选择并验证目标后再操作。
  当前窗口与独立窗口采用不同的任务 session 后缀，保持 pin-tab；连接失败不得静默创建替代窗口。
- 当前浏览器共享用户已有登录状态。独立 control session 不代表独立 profile，也不代表域名级网络隔离。
  不迁移 Cookie、不重启用户浏览器、不对外暴露调试端口，退出任务时保留借用的标签页。
- 常规控件使用快照引用；画布等区域可用同一标签页的视口截图和浏览器坐标事件补充，并核对操作结果。
  这不是操作系统级鼠标控制。CLI Skill 是模型可读的操作政策，不把它表述为强制拦截任意 shell 命令的安全边界。
- 不改变插件 ctx.browser 的 source、namespace、域名授权、profile 或宿主生命周期合同；它与 Agent CLI
  仍是两条调用面。ADR-0090 关于 Agent 默认独立浏览器的使用指引由本文更新，其任务 session 所有权继续有效。
- 输入区的 Connector 与展示层以普通 children 组合调用方拥有的新会话设置控件，不把新会话状态并入输入框 model。
  默认 Recipe 将控件放进输入面；已有主题覆写若只消费原 model 合同，则在覆写视图前保留这些控件，防止入口消失。
  新会话设置控件使用 CSS 容器查询，在窄栏把项目与智能体排至模式下方的第二行；不依赖 hero 或测量 observer 的生命周期。

## 备选方案

- 所有网页操作改为屏幕坐标：普通表单定位会更脆弱，也不能解决选错浏览器或标签页的问题。
- 自动复制用户 profile 后另开窗口：无法保证用户所见页面一致，并扩大凭据与配置访问面。
- 改写整个输入框状态模型：把新会话设置与进行中会话状态混在一起，增加团队及扩展适配成本。

## 后果与边界

部分浏览器需用户先开启兼容的本地连接设置。自动发现能力由锁定的 agent-browser 版本提供；
不承诺所有浏览器、系统弹窗或 OS 桌面都能接管。显式独立浏览器仍支持任务 profile 与多账号工作流。
这次不更改已有会话、模型、登录数据或正在运行任务的上下文，不自动重发返回空回复的收费请求。
