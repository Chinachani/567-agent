# ADR 0140: 桌面分组凭据与逐请求签名

状态：2026-10-24 本地候选；不变更线上服务、不发布。

## 背景

默认分组按名称前缀复用令牌，会选到专用生图组；达到令牌上限时又可能改用或改写其他分组、用户自建的令牌。模型接入时生成的签名写进 models.json，后续回合重放相同时间戳与 nonce。余额强制刷新同时绕过了普通缓存与 429 冷却。

## 决策

- 默认组只复用名称及实际分组匹配的应用令牌；专用组可复用实际分组一致的有效令牌。满额、列表不可读或明文密钥不可读时停止，给出可恢复错误，不改写其他组的凭据、不从列表首项兜底、不重复建令牌。
- 模型配置只持久化稳定的 X-567-Group。读取旧受管配置时过滤客户端、设备、时间戳、nonce、签名等动态字段；正常保存时不再写回。第三方 provider 的自定义 Header 不受此迁移影响。
- 签名属于 Desktop 宿主。复用 AI 公开的 fetch 注入合同，在每次实际 HTTP 尝试前生成新证明；供应商 SDK 重试也经此边界。通用 AI 包不持有 Desktop 客户端签名材料。
- 模型调用开始时绑定其有效地址和分组。仅对受管 provider 的可信服务地址签名，传输中不跟随重定向，也不接受换源或越出 /v1/ 的请求。继续保留授权、正文、AbortSignal、流式事件、usage 与模型调用重试语义。
- 主运行时、能力调用、调试调用和 Desktop 的 RPC 子进程使用同一请求准备函数。macOS/Linux 保留 Electron `--agent-rpc` 入口；Windows 保留 `ELECTRON_RUN_AS_NODE` 和既有制品路径，打包内容改为 Desktop 专属装配入口，注入同一签名流与线路运行时。签名/设备身份、文案引擎与 Electron 安全存储/系统语言读取分开，Node 子进程不加载 Electron API，也不降低凭据存储要求。CLI 宿主新增可选的 streamFn 注入口，转交既有 Runtime 组合口；无注入时沿用默认行为，通用 CLI 不依赖 Desktop。
- force 只跳过普通余额缓存；429 冷却始终生效。冷却中无缓存则返回失败，有缓存则保留缓存；到期后的并发刷新仍由既有单飞合并。

## 备选方案与验证

未在通用 AI provider 中添加产品专用密钥或全局 fetch 补丁，也未把动态函数写入持久化模型协议。选择宿主请求边界和可选运输注入，避免跨包反向依赖及难以恢复的全局副作用。

回归覆盖先接生图再接默认组、令牌满额和读取失败、旧签名读取过滤、真实 OpenAI SDK 经模拟 fetch 连续回合及传输重试、分组头绑定、无签名的第三方 provider、换源拒绝、带/不带缓存的强刷冷却和到期并发恢复，以及 RPC 宿主完整回合。使用真实打包函数构建 Windows Node 入口，在隔离目录内执行两次 IM 回合并核对实际传输头；这不替代真实 Windows 原生安装矩阵。全部使用隔离目录和模拟传输，不调用真实模型或订单。

此修复不为已误配的历史模型文件自动重建远端令牌；用户重新接入相应分组后，会按正确规则重新选择密钥。不会删除任何用户令牌。
