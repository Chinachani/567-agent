# ADR-0156：宿主支持自定义 OpenAI 兼容图片服务

- 状态：已实现
- 日期：2026-11-06

## 背景

上游增加自带密钥的图片服务配置。本地已有 `ctx.media`、媒体注册表、加密凭据库和按模式选择服务的设置，不应让图片插件另建网络、凭据和路由体系。此次增量在 Desktop 媒体域适配，保留内置 567 API 的默认优先级及既有图片历史。

## 决策

- 自定义服务由主进程注册为 `custom-openai:<id>`，仅支持 OpenAI 兼容的 `/images/generations` JSON 与 `/images/edits` multipart 协议。Base URL 包含服务的版本路径，至少启用文生图或图生图之一；每台设备最多保存 20 项。不改变 `ctx.media` 协议或插件权限。
- 设置 → 模型 → 图片复用现有两种模式的路由选择，并提供新增、编辑和删除。表单只写 API Key，列表只返回 `hasApiKey`。空密钥编辑保留原值；更换 URL 来源必须重新输入密钥，防止旧密钥发往新域名。修改后未保存的草稿需确认才丢弃，失败保留输入。
- 元数据采用 schema 1，保存在当前用户数据根的 `desktop-app/custom-image-providers.json`。密钥加密保存在已有 CredentialVault 的 `image-providers` 命名空间；不存于元数据、Renderer 读取结果或日志。
- 保存使用文件锁，锁内重读防止多个实例覆盖。新密钥先写独立 revision，再原子提交引用它的元数据，最后更新注册并清理旧密钥；元数据写失败时原配置与有效密钥不变。删除先提交元数据，再卸载服务和清理密钥。损坏的配置明确报错，不用空配置覆盖。
- 这不是跨文件数据库事务：旧密钥清理失败可能留下不再被元数据引用的加密记录，并记录不含密钥的警告；不影响当前服务选择。既有内置 Provider、插件旧凭据和其他 Vault 命名空间不迁移、不删除。
- 新 CRUD IPC 仅接受可信主窗口 Renderer，入口校验后交给独立媒体配置服务；错误返回稳定代码，不传原始异常。注册生命周期沿用媒体注册表，卸载或重配取消在途请求。
- 请求复用 Desktop 网络代理。URL 只允许无内嵌凭据的 HTTP/HTTPS；重定向拒绝，下载图片只在与 Base URL 同源时携带 Bearer。错误内容有大小上限并隐藏密钥；图片最多 32 MiB，JSON 响应最多 45 MiB。图生图限制一张参考图，先检查大小；取消贯穿请求和产物写入前检查。只保存受支持的图片格式，不执行返回内容。

## 备选方案

- 直接恢复插件内的自定义 HTTP 配置：重复宿主路由与凭据职责，放弃。
- 整体覆盖上游媒体模块：会替换本地 567 API、代理和安全边界，放弃。
- 把任意图片服务都当 OpenAI 兼容：协议和计费含义不一致，因此只支持声明的两个端点，不做自动猜测。

## 验证与边界

使用临时目录、真实元数据/Vault/产物装配和可控网络边界，覆盖新增、重开、编辑、密钥轮换回滚、多实例、损坏配置、取消和删除；可信 IPC 及真实设置组件覆盖连续操作、焦点、确认与失败恢复。未调用真实付费服务。

自定义服务的费用、尺寸、可用性和内容规则由对应服务决定。此实现不代表所有标称 OpenAI 兼容的服务都支持图生图，不自动检测协议或保证输出尺寸；内置 567 API 的服务端规则继续独立生效。
