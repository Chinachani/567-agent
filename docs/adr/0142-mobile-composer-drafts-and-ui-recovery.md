# ADR 0142: 手机草稿持久化与双端 UI 失败恢复

状态：2026-10-24 本地候选，未发布、未安装。

## 背景

手机草稿和待发附件原先只在 ViewModel 内存中；进程重建会丢失，并且原有空电脑会话清理无法识别持久化草稿。桌面设置和账号弹层又有失败反馈、确认与模态行为缺口。直接把大附件放进 Compose saved state 会增加恢复负担，重启已经 stop 的原生远控对象则会访问已释放的资源。

## 决策

- SessionStore 增加 getDraft/saveDraft/hasDraft。SettingsSessionStore 在原有 IO mutex 内维护独立 v1 草稿索引，按本地会话与账号 ID 区分；没有在线账号的配对会话使用配对身份，无账号与配对时使用本机身份。已登录但账号 ID 尚未确认时暂不跨身份恢复。记录删除时清除该会话所有草稿，迟到保存不会重建已删除会话。
- 文字与附件元数据进入设置索引；图片和文档字节写入现有应用私有文件存储的独立随机键，遵守已有附件数量与大小限制。恢复时读回原始字节，发送消息另存附件；清除草稿不会删除已发送图片。写失败保留页面输入并明确提示；读失败保留原存储，不把损坏草稿当成空内容。
- ViewModel 串行保存快照，先显示会话页面，再后台恢复；账号代次、所有者、当前会话与后续编辑共同防止迟到读取覆盖。切换会话同步清除旧消息，历史订阅再次核对当前会话，避免旧完成结果短暂挂到新会话上。已保存的非当前会话释放附件内存。只有对应用户消息已落盘后才消费匹配的草稿，保留发送准备期间的新输入。退出保留聊天记录时保留按身份隔离的草稿；清除本地记录同时清除草稿。聊天迁移备份合同不变，尚未发送的草稿不进入备份。
- 空电脑会话清理增加持久化草稿检查（包括其他账号的草稿）；读取失败时保留会话。持久化草稿与正常消息保持各自所有权，不把未发送内容伪装成历史消息。
- Android uiMode 由 Activity 显式处理，Compose 继续收集主题配置。昵称和充值金额等轻量编辑状态使用 rememberSaveable；密码、令牌、兑换码和原生连接对象不写入 saved state。supportsRtl 保留为 Android 的布局能力声明，并不表示新增了手机多语言；本轮中文文案集中到现有 Str。
- 远控重试通过 Compose 的连接代次创建新 NativeRemoteDesktopSession，旧实例由 DisposableEffect 释放；preview/fullscreen 仍共用该代次。明确退出后不再创建原生 renderer，系统授权与输入能力仍由原合同控制。设备资料缺失时渲染可返回的恢复页，避免在 composition 中触发导航。
- 桌面保存返回明确成功结果，调用方只在成功时关闭编辑器。删除与退出接入现有 confirmDialogAtom；原业务 hook 继续拥有实际删除、状态刷新和失败提示。分组移除保留既有撤销对应 567 Agent 服务端令牌的行为，确认文案明确告知，不把它描述为仅本地删除。充值使用共享 Radix Dialog，并显式开启初始焦点及归还焦点，关闭后阻止迟到请求推进付款视图。

## 备选与后果

不使用单一全局草稿或 saved state 大字节载荷，也不自动重发恢复的内容。草稿字节留在应用私有目录，与现有本地聊天数据相同，未新增远端存储。系统强制终止发生在 IO 完成之前时，最后尚未完成的编辑仍可能丢失；UI 不承诺同步磁盘写入或崩溃事务。无效文件保留并提示，用户明确编辑、发送或删除后才更新。

验证覆盖保存失败与重试、四类确认、分组三态、付款焦点与迟到结果、草稿文件重建/账号隔离/发送清理/迟到恢复/空会话保护、远端删除重试及格式化边界。Android UI 用例已补入设备测试编译，真机操作仍由用户执行。具体结果见本轮复审修补记录。
