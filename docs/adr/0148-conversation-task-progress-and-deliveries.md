# ADR 0148：会话任务状态、明确恢复与交付投影

日期：2026-10-28

## 背景

目标模式已有目标状态、暂停和恢复，Runtime 已有失败恢复、输入队列暂停与 continue。Renderer 也有工具阶段、提问、计划审批、重试和压缩投影，但这些事实分散在不同展示位置。Markdown 文件列表属于正文，不能代替按会话查找交付结果。

## 决策

- Runtime 的 ConversationDocument、持久化历史与现有事件继续是事实源。桌面新增只读任务状态选择器，汇总现有 atom 和末条回复；不维护另一份任务生命周期，不增加消息存储格式或自动执行入口。
- 普通失败或停止的回复通过既有 `session.continue` 开下一轮；已有目标通过 `resumeGoal` 恢复。两者都由用户明确确认，不删除历史或重发原用户消息，不修改草稿，不保证模型不会再次提出相同操作。确认说明新请求费用与外部状态核对要求，现有工具权限不变。
- 恢复绑定运行时、回复与目标身份；确认期间切换会话、新回合开始、目标状态变化或存储失败均拒绝过期操作。存在待处理输入的暂停队列通过原队列入口恢复，不能由新按钮绕过。空的暂停队列不阻止继续。
- 交付区进入现有 ActivityPanel。索引在首帧绘制后分批从助手历史、成功工具结果与图片原始路径派生；流式正文增量不触发重新解析，切换身份或来源会取消旧投影；提取失败提供原位重试。排除用户附件、代码示例和未结束的文本。来源使用消息流公开稳定 key，以兼容乐观消息、持久化 entryId 和聚合 renderKey。
- Markdown 资源提取复用现有 parser、异常链接修复与链接分类，不引入另一个正则链接协议。只索引允许的本地文件和无凭据 HTTP(S) 目标，原有打开、复制、预览与主进程安全检查继续生效。
- Node 写入和编辑工具在成功结果的开放 `details` 中新增可选消费的 `writtenPath`，值来自实际输出路径；拒绝、失败和取消结果不提供成功写入证据。保留已有 `fileChange`、工具文本和副作用顺序。桌面在首次投影边界校验路径类型与长度，并兼容历史 `fileChange.path`。旧消费者忽略新增字段，旧记录缺字段时仅展示其已有引用。
- 交付证据只区分“对话引用”和“工具已写入”。两者都不证明文件仍存在、内容正确、网站可访问或任务验收完成；不自动联网验证，不通过索引扩大文件读取授权。
- 运行、等待及失败状态可见；正常回复结束后收起状态条，保留轻量交付入口，不增加成功百分比或剩余时间猜测。

## 备选方案

新建任务数据库、恢复队列和产物注册服务会与现有 Runtime 重复，并要求迁移。直接在 ChatView 或事件控制器中累加业务状态会增加耦合，且易在历史重开和会话切换时漂移。采用独立选择器、窄恢复 hook、纯 View 与既有面板注册合同即可覆盖当前目标。

## 验证与后果

覆盖明确恢复、拒绝陈旧确认、重复点击、草稿保留、目标与队列边界、实际文件名纠正、历史投影、代码与恶意链接排除、来源定位及主题窄窗。原有 Runtime continue、重启恢复、队列和目标合同一起回归。

索引没有持久化副本，随历史和分支重新计算；它只覆盖当前已加载会话，不能发现 shell 或未知插件未报告的全部输出。工具成功后文件可能被删除或修改，后续打开失败仍由原文件预览和错误路径处理。手机继续消费现有历史和协议，本次任务工作区呈现在桌面。

## 反馈调整（2026-10-28）

正常结束的回复也提供轻量的“从历史继续”，复用同一 Runtime continue 及确认合同；不把正常结束标成失败，不追加或重发原用户消息。状态条与输入框同宽，运行中停止动作只保留输入区入口。paint 前后两次身份校验失败均反馈状态已变化。
