# 可配置的单轮模型调用预算

## 背景

运行时默认每次执行最多调用模型 100 次，长任务触顶后以 `max_model_calls` 结束。用户要求在设置中调整次数或关闭本项限制，同时保持历史、线路、草稿、协议与既有运行生命周期兼容。

## 决策

- 产品配置 `coding.model-call-limit` 复用已有 Runtime Configuration Center、配置 IPC 与加锁 settings.json 存储，持久字段为 `modelCallLimit: { enabled, maxCalls }`。默认开启 100 次，次数必须为正安全整数；关闭保留上次数字。旧配置缺字段保持原默认，无需重写历史。
- Desktop 设置 → Agent 配置提供常驻“任务执行”区块，独立于模型 Token 容量与高级动态配置表单。开关、输入、预设均先编辑草稿，保存后生效；输入无效或保存失败时保留草稿。触顶错误提供直达设置动作。
- Agent Core 的 `maxModelCalls` 以显式 `null` 表示只关闭模型调用预算；省略仍保留有限默认值，不使用 Infinity、0 或巨大数字模拟无限。现有状态、错误、取消、用量与工具合同保持。
- Runtime 的宿主注入点 `resolveTurnLimits` 在执行起始读取一次并投影为本轮独立预算；同一个 Session 后续执行会重新读取，在途执行保持原值。Coding Agent 只转发端口，Desktop 选择当前配置，Runtime 不读磁盘、不拥有 UI 设置。
- 关闭模型预算后，工具次数仍默认 1,000、checkpoint 仍默认 300 秒，恢复尝试预算保留有限的 100 次。配置有限模型预算时保留原先恢复预算跟随该值的语义。手动取消始终保留。
- 复用的运行时配置 IPC 补齐可信主 Renderer 来源校验；其他窗口、子 frame、分离 frame 和销毁 owner 不得修改设置。
- 手机远程 Session 使用 Desktop 执行预算；手机 API 纯聊天没有同一个 Agent 循环，不增加无效开关。

## 备选与边界

直接删除 100 次检查会改变所有用户的默认行为，不能表达按需选择。用超大数字或 Infinity 冒充关闭会混淆序列化、校验与其他预算；采用显式 null。新增独立配置文件或 IPC 会形成第二套设置路径，现有配置中心可直接承载本项。

## 验证

确定性模型流验证超过 100 次正常完成、有限预算截断、关闭后的取消/工具/恢复预算；Runtime 同一 engine 跨轮读取与在途不变；真实 Desktop backend pool 串联配置保存、触顶、继续和历史保留。设置组件验证先绘制后读取、关闭重开、校验、保存失败重试、恢复默认与语言切换不覆盖草稿；配置 IPC 验证来源拒绝和持久化接线。无需真实 Provider 或付费请求。
