# ADR 0147: 旧默认线路迁移与设置 IPC 来源校验

- 状态：已采纳
- 日期：2026-10-27

## 背景

1.4.0 在首次启动时可能将尚未开放的大陆线路自动落盘。1.4.2 仅修正缺失配置的默认值，不能修复这些已落盘的配置。直接替换所有大陆地址会覆盖用户选择，手机更早版本还允许手工保存服务器而不记录线路历史。

设置 IPC 虽校验参数，却没有像会话工作台一样校验调用所属窗口和 frame。手机 Responses 和 Completions 解析器把生图进度硬编码到任意函数调用，混合了协议事实和界面文案。

## 决策

- 桌面仅将 `route: mainland` 且完全没有 `knownOrigins` 字段的旧配置视为自动默认，读取时迁为德国，并沿用初始化写盘。正常主动选择会写 knownOrigins。已有字段即使为空或无有效 origin 也保留为记录，避免下次归一丢弃后误迁移。不改变 schemaVersion，自定义和其他线路原样保留。
- 手机仅迁移精确的内置大陆 origin、没有旧 `vetta.prefs.server_url`、没有线路选择记录、没有显式服务器选择标记的 canonical 配置。更早手工配置与存在但无法解析的选择记录保守保留。显式 setServerUrl 新增布尔选择标记，先写标记再写 URL，避免中途退出使已选值被当作默认。迁移复用现有 server URL 键，不修改账号、模型或会话数据。
- 选择记录只为正常产品操作提供证据。用户手工写入恰好与旧自动默认完全相同且无来源记录的配置无法区分；来源不明且有记录的配置不自动切换，可从登录页修复。无需网络探测或收费请求。
- registerSettingsIpc 接收当前主窗口 WebContents，在六个 handler 的业务动作和参数处理前调用既有 assertTrustedMainRenderer。拒绝其他窗口、子 frame、缺失 frame 和已销毁 owner；窗口重建沿既有 IPC 注销再注册生命周期。
- 两种手机解析器只输出工具事实，不填本地 UI phaseLabel。界面沿用 Str 的工具类型标签与生图进度回退，实际远程 progress 文案继续显示；不修改工具释放终态、参数、取消或 usage 语义。
- 通用 model.api / modelOverrides.api 继续允许注册的自定义协议。设置 IPC 的两种 OpenAI 协议选择限制不扩散到插件合同。

## 备选方案

- 无条件迁移大陆地址：无法保留用户选择，拒绝。
- 首次网络失败后静默换线路重试：可能改变身份边界并重复请求，拒绝。
- 全部旧配置弹窗阻塞启动：正常产品选择已可用记录识别，无需增加阻塞流程。
- 在 Core 引入 UI Str：违反职责方向，拒绝。
- 把通用 api 收紧为两值枚举：破坏第三方适配器，拒绝。

## 后果与验证

迁移对已完成记录幂等；之后用户主动选回大陆会保留。自定义服务、已选线路和模型自定义 API 不被修改。新增失败基线与升级→选择→重启流程，IPC 允许/拒绝/注销合同，以及解析结果到本地工具状态的回归。测试使用临时目录、内存偏好及本地 fixture，不读取或改写用户配置，不做真实服务探测。
