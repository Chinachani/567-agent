# ADR-0160：复用分片下载核心与映射后的 Wayland 直接点按

状态：已实现
日期：2026-11-11

## 背景与备选

更新下载已有校验和分片能力，普通文件下载仍独立实现单连接，暂停期间过早释放队列槽位，可能让旧请求覆盖新状态；请求头也未按任务隔离。Android 的手写 URLConnection 连接管理缺少可复用的连接池。手机已有绝对坐标手势，但 Wayland 输入只有相对移动，不能按画面位置直接点击。

评估了 aria2、EasyDl、SteadyFetch 等开源下载项目。外置 aria2 增加跨平台原生分发与进程生命周期；EasyDl 当前范围处理不足以直接替代更新包的严格范围和摘要合同。采用已有开源网络栈及当前可验证的分片核心，避免将安装、验签和用户下载迁入另一套持久化系统。Android 直接声明当前 Ktor 已依赖的 OkHttp 4.12.0，不升级其版本。

## 决策

- Desktop 提取同一个流式 Range 下载核心给完整更新包和普通文件下载使用。更新包继续强制官方摘要，不改差分与安装。普通文件仅在有强 ETag 时分片和续传，无可靠身份或范围支持时单连接重下；无标识文件在同一次任务的失败重试中也重新下载。验证 Content-Range、响应体长度与 If-Range，不把 416 直接认作成功。
- 文件下载保留原列表合同；最多两个文件任务、每文件四分片。暂停/取消保留活动槽位直到网络及文件句柄收尾，旧回调不能改新状态；请求头仅存当前进程每任务内存，跨源重定向剥离私人头。分片放应用 cache namespace，完成内容先暂存到目标盘，再以独占方式发布，不覆盖其他进程新建的目标文件。
- Android 使用 OkHttp 连接池与最多四分片，保留私有目录、前台服务、摘要/包名/版本/签名校验及系统安装确认。旧两分片无计划缓存继续按两段坐标恢复，新任务保存分片计划。
- Wayland 直接点按使用用户授权的 RemoteDesktop+ScreenCast portal 会话及 NotifyPointerMotionAbsolute；仅当桌面明确知道捕获的是主显示器，且 portal 返回的唯一 monitor 的位置、尺寸与目标匹配时启用。组合会话不支持或选择屏幕失败时关闭本次绝对映射请求并重新建立相对输入会话；明确取消 RemoteDesktop 输入授权仍按用户决定失败。窗口、未知来源或映射不匹配保留相对触控板；不以图片尺寸猜位置，也不使用 XWayland 绕过系统输入授权。
- 输入能力通过已有 capabilities 的 pointerMode 动态更新；手机允许在平板点按与触控板间切换并保存当前页面偏好，系统不支持时给出说明。保持旧布尔 input-permission 内部通知兼容，不改变线协议版本或扩大 inputEnabled 权限。

## 后果和验证

分片不保证每条网络固定提速；服务器无范围/身份信息时优先完整性。旧下载记录保持可读，凭证不落盘；旧更新分片及两段 APK 可恢复。Wayland 直接点按仍取决于门户返回可映射的整屏来源，不保证所有桌面环境或窗口共享可用。

本地 HTTP/真实文件系统验证下载→暂停→继续→完成、队列与凭证隔离、范围异常、目标冲突与无长度回退；portal 边界测试验证授权、坐标匹配、撤销与模式协商；Android host 和 Compose UI 测试覆盖四段和旧缓存恢复、模式选择与触摸坐标。真实平台和设备验证按实际执行结果记录。
