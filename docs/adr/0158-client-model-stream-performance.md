# ADR-0158：模型流速度观测

- 状态：已实现
- 日期：2026-11-09

## 背景

消息统计只有 Token 和缓存数据，整轮耗时包含工具执行，不能用于推断首字延迟或模型生成速度。历史记录没有足够时间信息，不能倒算精确速度。

## 决策

- 在 AI 层已有的原生和兼容流生产入口记录单调时钟，向成功结束的 `Usage` 增加可选 `performance` 字段。记录流创建至完成耗时、第一段非空正文和首次文字/思考/工具输出。只保存相对毫秒数，不存正文或服务器时钟。
- 在生产者 push 时测量，防止消费端排队影响时间。内层流已有计时时，转发层保持原值；错误和取消不计为成功样本。终态消息、result 和 metadata 的 usage 保持同一测量值。
- 现有消息/历史/IPC 继续传递完整 Usage；同步扩展 Runtime Storage 的严格 Usage Schema，只接受可选、非负有限数的计时字段，保留其余字段校验。无新事件种类、请求参数或数据迁移。旧历史没有计时显示“未记录”。旧客户端的严格 Schema 不认识新字段，因此新版本写入的计时记录不能保证可降级读取。非流式接口不伪造首字。
- 流的计时状态由构造器闭包持有，保留已有结构类型兼容；终止后的额外事件不再观测。扩展 Adapter 返回冻结 Usage 时跳过可选统计，不让观测导致模型调用失败。
- Desktop 的平均首字为有效正文样本的算术平均，模型用时为有效调用时长之和，TPS 为有有效生成区间的输出 Token 总数除以生成时间总和；不对单次 TPS 直接平均。生成区间从首次非空输出至完成，包含已流出的思考/工具参数及传输时间，不含工具执行和调用间隔。
- 不改变计费 Token；供应商输出 Token 口径可能包含隐藏思考，界面解释该限制并显示计时/首字/TPS各自样本数。
- UI 复用原 Popover，速度区为纯展示叶子；数据汇总、范围切换与本地化归 Desktop。正文使用界面字体和 12px 字号，数字使用 tabular-nums，浮层受视口约束并可滚动。

## 备选方案

- 用整轮耗时计算 TPS：混入工具和排队时间，不采用。
- 仅在 Renderer 接收事件时计时：历史无法恢复、后台与 IPC 排队会失真，不采用。
- 改动每个 Provider 的协议：重复实现且口径不一致，复用统一流入口。

## 验证

覆盖原生/兼容流、延迟消费、思考后正文、纯工具调用、失败/取消、冻结对象、终态后事件、严格存储校验与真实临时文件关闭重开、加权汇总、历史缺值、实时与历史投影，以及打开浮层→切换统计范围→Escape 返回触发器。未使用真实付费模型或用户会话进行测试。
