# 命令工具的内存与输出保护

## 背景

第三方图片工具的瓦片圈数被当作距离使用时，可能申请数百 GiB 的画布。仅靠系统提示词、超时或 shell 输出截断不能阻止分配；系统 OOM 还可能停止与该工具同组的整个桌面应用。

## 决策

- Node 命令进程的保护属于 `runtime-node`，在现有前台、后台、SDK 命令和三种平台沙箱的进程边界复用。同一个宿主只运行一个有界、不重叠的内存采样器。
- 默认单个命令进程树预算为可用硬件或容器总容量的四分之一，最高 8 GiB；本宿主全部命令合计预算为总容量的一半，最高 32 GiB。机器总容量不足时进一步缩小。宿主环境变量可设置正整数 MiB 预算，但最高不超过总容量的 75%，命令自己传入的 env 不能改变预算。
- 启动预算进一步取当前可用内存的一半；可用内存低于 64 MiB 时拒绝启动。监控发现剩余内存低于总容量的 10%（最高预留 2 GiB）时结束最大的命令。Linux 读取包含可回收缓存的 `MemAvailable`，并兼顾 Node 识别的容器约束，避免把正常缓存误判为耗尽。
- Linux 数据分配上限取命令预算与 1 GiB 的较大值，以容纳 Node 24 的 CodeRange 预留；较小的 RSS 预算继续由采样执行。原本直接使用低预算作为 DATA 上限会阻止正常启动，不能把这种故障当作资源消耗超标。
- Linux 在执行原命令前设置并继承 `RLIMIT_DATA` 的软、硬上限。保持更低的已继承硬上限；设置失败则不执行命令。使用 argv 转发，保持原命令、引号和 shell 的含义，不拼接模型提供的文本到保护脚本中。
- 各平台采样命令进程树的占用。单树超限时结束该命令；合计超限时结束占用最多的命令。Windows 采样取工作集与私有提交量的较大值，POSIX 采样 RSS。失败沿已有 error 路径传播，并在管道关闭后释放采样记录，不能仅以根进程退出为释放条件；取消、超时与结束仍由各命令宿主负责。
- 命令合计 stdout/stderr 默认最多 32 MiB，避免父进程收集输出或写入队列消耗无限内存。超限时提示把大量输出写到文件，再读取有限区段。
- 内存分配失败和监控超限都返回带改进建议的受控错误。后台任务没有正常退出码时仍根据失败或停止状态报错，不能投影为成功。
- 产品提示词与 shell 工具描述要求 AI 先查参数单位、预估尺寸和并发内存，采用小区域、低分辨率、分块或批处理；收到保护错误后先缩小任务，禁止原样反复重试或绕过限制。

## 备选方案

只修改提示词不能防住模型错误。只给特定 skill 添加命令字符串匹配会遗漏其他程序并改变 shell 语义。使用地址空间上限会影响 V8 大量保留虚拟地址的正常启动。因此选择 Linux 数据分配限制加通用进程树监控，并单独修补出错工具本身的输入边界。

## 后果与边界

大规模构建、图片或本地模型任务可能需要分批处理，或由用户明确配置更高预算。命令文本和凭证不进入采样器日志。

RSS 采样属于尽力保护，有采样间隔、进程退出与共享内存重复计数的限制。Windows/macOS 本轮没有新增内核 Job/cgroup 级上限；Linux 数据限制是每个进程的可写分配限制，进程树与合计预算仍靠采样。它不限制 GPU 显存、第三方服务或已脱离命令生命周期的常驻进程，也不构成针对恶意特权程序的隔离承诺。
