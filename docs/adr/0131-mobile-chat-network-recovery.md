# 手机聊天的断网状态与远程任务恢复

## 背景

等待首字时，HTTP 流已经可能被服务端接受，不能通过自动重发保证恢复。远程电脑任务则独立于手机网络，但此前手机在断线时立即终结本地回合，替换连接还会丢失事件序号。

## 决策

- Android 观察默认网络的可用性，区分等待模型回复与已经输出内容。没有网络时保留草稿；手机 API 响应断网时取消失效请求，并在不可取消的清理阶段保留消息、部分回复和失败状态，再释放发送门禁。取消中的旧任务不得清空新任务状态。
- HTTP 请求被接受后不自动重发；没有请求 ID 查询接口的服务端无法保证继续原响应。用户在网络恢复后可明确重试或发送新消息。
- 远程提示带随机 `turnId`。电脑保存有界的任务进度快照，按会话与提交内容校验同一标识，防止重复执行。新增只读 `session.turn.read`，在 `session.list` 中协商后调用。会话所有权、活动任务、问题应答和快照在同一次远程连接服务运行内共享，替换信令 Connector 或在局域网与中继之间切换不会丢失；迁移接收许可仍按各连接来源独立检查。
- 手机远程断线后保留正在执行的回合，在连接恢复后按原任务标识拉取文字、工具记录、待回答问题与用量快照。快照替换当前回复，不拼接重复文字，也不执行工具。恢复过程不再次发送 `session.prompt`。
- 按信令来源保留已接收序号，并识别电脑重启产生的新事件来源；恢复快照携带电脑当前事件游标，可在完整快照应用后越过丢失的增量事件。
- 每次等待连接恢复最多 90 秒；连续三次读取失败则终结本地等待并保留记录。旧电脑、已清理的快照、电脑重启或远程连接服务被停止后没有同一任务记录时，明确提示检查电脑会话结果，禁止猜测任务是否需要重发。

## 后果

手机 API 与远程电脑的恢复能力不同。远程恢复需两端更新，且依赖当前电脑远程连接服务保留的快照；完成任务最多保留 16 条，活动任务不会被清理。停止远程连接时清空快照。停止等待和取消任务仍由用户明确操作。网络监听只判断是否存在默认网络，不要求互联网验证成功，以保留局域网连接能力。

恢复快照以完整序列化 UTF-8 大小控制在 900,000 字节内，给响应外壳和事件游标保留空间。必要时舍弃较旧工具详情并截短文字，标记 truncated；手机结束后重读历史。问题与终态优先保留，元数据自身超限返回可操作错误。相同问题保留本机未提交选项，已答复的问题在两端恢复缓存中清除，避免轮询复现旧表单。
