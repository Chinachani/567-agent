# ADR-0164：纯提示词专家来源与恢复边界

日期：2026-11-17

状态：源码已实现，完整静态检查、Desktop main/preload/renderer 构建和 Android 主代码编译通过；未执行行为测试或设备验收。

## 背景

独立专家仓库已提供源码索引、提示词与头像，但未发布通用插件安装索引和制品。
将其放入能力安装列表会同时造成同步失败、入口误导和额外插件启用步骤。用户希望在智能体页直接发现与使用专家，复制后仍可独立编辑。

## 决策

1. 复用现有多仓库管理、归档缓存和来源配置；只有明确识别的专家仓库允许读取源码索引。专家条目从普通能力目录过滤，进入「智能体 → 专家」。
2. 沿用插件清单中的专家声明格式，但用窄 `AgentPresetPackage` 投影读取提示词、头像和翻译。拒绝路径逃逸、符号链接、过大资源、身份接管与可执行能力贡献，不加载插件入口，不授予权限。
3. 新快照须全量校验成功才替换。以完整归档摘要识别版本，服务端支持 ETag 时使用条件请求；304 必须再次校验旧快照，损坏时无条件重新下载并替换。
4. 来源状态独立于档案加载。失败保留旧有效快照并显示原因；后台错误也广播。完整快照才可删除旧声明，早期预览版的已知插件归属专家在首次同步前受保护。
5. 网络同步串行应用，结果读取后再次检查来源身份。本地插件可用性立即更新，不等待网络队列；真实安装的同 ID 插件优先于源码投影。
6. 专家原件只读。复制时冻结提示词与当时能力选择，后续不再继承提供方的固定插件能力；蓝图失效不使完整副本失效。缺少提示词的原件即使通过深链也不能生成空副本。
7. 专家语言解析在共享展示层进行，支持完整区域语言、基础语言和确定性的同语言回退。首批专家按已核对 ID 分类，不从提示词推断类别。

## 备选方案与代价

- 等待独立仓库发布可执行插件：遵循通用分发路径，但无法立即满足纯提示词发现需求，并增加安装与启用负担。
- 新建专家协议与独立市场：需要另建下载、来源和缓存机制；当前需求可用已有声明的严格子集完成。
- 跳过坏包应用剩余内容：会把暂时失败误判成作者撤回专家，因此保留整轮原子性。
- 仅比较源码索引：提示词改动可能不更新索引，因此使用完整归档身份；没有 ETag 的服务端仍需下载归档。

副本冻结不意味着远程执行能力随之授权。用户仍通过现有模型与权限配置使用专家。
通用插件发布流程与本次源码读取分别维护，本轮未向独立仓库发布索引、制品或 npm 包。

## 相邻手机与远控改进

本轮还沿用既有协议完善恢复体验，不引入新的远程权限：

- 分享文字先选择草稿目标，在异步读取后合并最新草稿并保留附件，不自动发送。
- 目标会话或草稿读取失败时保留分享文字供重选，不覆盖其间收到的新分享。
- 网络恢复只唤醒已有重连等待，任务中心汇总当前进程内不同手机会话的运行状态；按电脑与远程会话身份去重，同时保留尚未在本地显示的待回答状态。
- WebRTC 短断连等待最多 12 秒，输入释放失败保留待发松键，通道恢复后补发。
- 画面和工具栏共用指针状态；键盘遮挡通过显式平移处理，不缩放或重新定义视频坐标。平板保留方向，输入控件触控目标至少 48dp。
