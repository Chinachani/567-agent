# ADR-0163: 1.6 上游功能适配与本地合同保留

- 状态：源码已实现，静态检查与编译通过；未执行行为测试和实机验收
- 日期：2026-11-16
- 上游目标：`openvetta/open-vetta@73dddbb70d8d8be7319420dbb1ea90a8f84184d7`

## 背景

用户要求在 1.6 专家与会话协作改造基础上接入上游可用功能。两仓库没有可直接合并的共同祖先，567 已有品牌、模型三来源、下载与远控修补，不能用整树覆盖替代适配。

## 决策

1. 固定上游目标，逐文件三方适配。通用增量参考 `f52cefabc81a6f1ca200aaa89ae7f632f1c566cb`；SSH 和自动化分别补齐 `c89060cba^`、`0111d7cde^` 之后的必要前置。上游版本、品牌资源和与用户选择冲突的产品行为不直接复制。
2. SSH 分为 transport、runtime adapter、Desktop 主机/项目装配。主机配置单独版本化保存，更新串行化；密码只通过凭据引用访问，身份确认不绕过。本地项目继续原有路径，SSH 项目只经对应 transport 分派。
3. 自动化采用结构化 schedule/runTarget，迁移前备份旧存储；旧 cron 在 Plugin facade 转换，公共 Capability 使用新结构。失效项目/会话及历史 scene 暂停执行并保留历史；继续已有会话不提权。初始化、恢复和关闭必须共同遵守 acceptingSchedules 生命周期。
4. MCP 使用同一配置领域支持 global/project scope、SSE 和 `.mcp.json` 发现。项目来源只读，发现不等于批准执行，不另建绕过审批的启动路径。
5. 模型选择收敛到共享目录与选择器，增加收藏、推理档位和虚拟列表；设置页保留三来源标签和各自参数。配置默认模型通过读取最新配置后更新，避免覆盖服务商的新变更。新会话/新窗口不记忆其他会话最近选择的模型。
6. Plugin SDK 0.3.10、API 2.9 与 Capability SDK 0.1.3 同步合同、适配层和文档。新面板、顶栏和终端能力按独立权限声明；外部插件不得借 UI 注册取得命令执行权。旧插件 cron 兼容只留在 facade，避免多个调度事实源。
7. 文件定位、目录引用和宿主文件操作复用文件树适配器；等待展开完成后再次核对挂载与项目，迟到请求不能移动新项目焦点。输入命令面板使用实际设备像素对应的 hairline，保持非整数缩放时接缝对齐。
8. 保留 ADR-0162 的专家/项目会话协作、旧团队只读深链，保留 567 品牌、悬浮侧栏、指针外观、Range 下载、Windows 更新准备及图标修补、ADR-0161 的 Linux 采集隔离和手机端修补。上游旧团队工作页、全局 last-used 模型持久化和品牌替换不接入。
9. 共享 UI 按公开子路径导入，Desktop 的 `@vetta-org/ui` 源码别名指向目录，避免将 `/button` 拼接到 `index.ts` 文件上。补齐插件设置分组、下拉与 Splash 组件的公开导出，现有更新确认合同保持兼容。

## 预设市场边界

独立 `Chinachani/567-agent-presets` 已提交首批 18 位日常专家。1.6 将其作为第二个内置 GitHub 来源，按现有缓存和失败回退策略刷新；在仓库只有 `.vetta/marketplace.source.json` 时，客户端仅对该来源做受限兼容转换，并把可读的专家声明直接铺进智能体中心。源码预设不要求先安装 Module Federation 插件，也不会在能力页伪装成普通可安装能力。正式 schema v3 索引和不可变 Release 制品发布后优先使用正式索引；源码完成与公开制品分发仍是两个状态。

## 替代方案

- 整树覆盖会丢失本地修补、恢复已下线团队功能，并改变默认模型行为，未采用。
- 只复制叶子 UI 会遗漏 SSH、自动化与 Capability 的跨层合同，未采用。
- 继续保留各插件自己的模型选择器会造成能力与停用过滤不一致，本次迁移到公开 ModelPicker 并删除已无消费者的旧实现。
