# ADR-0166：对话阅读位置、来源与手机草稿

## 背景

参考 [DeepSeek chat-demo（固定版本）](https://github.com/deepseek-ai/chat-demo/tree/5d5dd754ebc1948e977ddb880a9eb5aa25f37b4c) 的版本选择器、流式显示及来源索引。567 保留原有虚拟列表、供应商协议、会话归属和可中断的工具执行。

## 决策

- **分支**：桌面只在当前可见选择器上记录持久 entry ID 和相对视口的位置。目标已挂载时按位置差校正，否则先由 Virtuoso 定位，随后有限次校正。用户开始滚动、离开或超时即结束本次定位。首次打开与切换其他会话沿用原行为。
- **来源**：文本块保留供应商实际给出的网页引用，UI 按首次出现的 URL 去重，后到的标题可补充。每条回复最多展示 32 个地址；只接纳不含凭据的 HTTP(S) URL。手机原生回复及电脑传来的消息均在输入边界核对。来源单独展示、点按后才打开，不访问站点图标，不给复制、朗读或下一轮模型输入添加标记。没有带结构化引用的旧数据仍按原文读取。恢复和分页先保留正文。
- **听写及重试**：听写只在设备支持离线识别时启用。接收结果时重新检查会话和最新草稿；若用户已编辑，追加到末尾。带文件的失败消息保留原回合，重新选择的文件和旧元数据核对后进入草稿。旧记录无内容摘要时明确告知限制。传输、发送、工具执行仍须单独触发。
- **写盘与显示**：普通编辑按账号及会话合并为一个待写快照；附件、发送清空、离开和进后台主动刷新。退出时等候写入结束并清理账号内存。流式 UI 与持久化检查点分别按 70 ms 和 1 秒的窗口合并，每路最多一个执行中的更新；发布期间到来的增量留给下一轮。首段以及工具、提问等边界主动发布。结束或停止时先收回两路任务，再保存当前回复；随后到达的图片只给对应消息追加图片，不改正文或状态。Markdown 合并使用帧间等待作为调度负担的近似值，并不等价于测得解析耗时。
- **收件箱**：读已缓存会话只取消息摘要；冷会话仅读取角色、状态、标识及时间，不创建详情流，不转存旧附件或修复聊天记录。读取失败时保留对应会话上次的结果、报告部分可用。详情缓存优先淘汰不再被观察、没有流式任务的会话。

参数是实现预算，不是实机性能指标。下一步可在授权设备上比较长表格、代码块、分支切换与断网恢复，对比可见延迟和写入次数。
