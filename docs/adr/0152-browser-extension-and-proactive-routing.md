# 当前浏览器扩展连接与主动工具选路

## 背景

ADR-0145 已让 Agent 优先连接当前浏览器，但 CLI 的 CDP 发现仍依赖浏览器启用本地调试。
Browser Skill 的模型可见简介只描述了工具名称与连接方式，没有充分说明已登录页面、网页交互验证等触发场景。
用户希望免浏览器启动参数并减少“请调用浏览器”的重复提醒。

## 决策

- 当前浏览器扩展使用微软维护的 Playwright Extension 与锁定版本的 `@playwright/mcp@0.0.84`。
  设置 → 通用设置提供安装官方扩展、启用/停用连接、可选授权令牌与浏览器配置目录名。
  内置三步安装指南；一键入口打开官方安装页并启用本机连接，指南另提供仅打开商店、复制链接和仅启用连接。
  商店打开、配置保存、扩展安装、实际连接保持独立事实；教程关闭重开保留参数草稿。商店打开失败时不写连接配置。
  只在用户点击启用后写入 `567-current-browser` MCP；打开设置不启动浏览器、不下载运行时。
- 设置页只读识别系统 HTTPS 默认应用，首次配置预选受支持的浏览器，并允许明确选择 Chrome、Edge、系统 Chromium。
  主进程按系统应用元数据和固定安装位置解析程序；可信 IPC 只接收浏览器枚举与 resolve/store/bundled 固定动作，不接收任意路径或 URL。
  安装页启动与下一轮 MCP 连接共用同一解析结果，不再以默认 Chrome 连接 Edge 中安装的扩展。
  固定版本 Playwright 的 `--browser chromium` 指向下载的测试浏览器，因此系统 Chromium 使用已解析的可执行路径和 Chrome 扩展通道。
  已识别目标通过现有 MCP env 保存 `PLAYWRIGHT_MCP_BROWSER`，仅 Chromium 或非标准安装保存 `PLAYWRIGHT_MCP_EXECUTABLE_PATH`（标准 Chrome/Edge 保留上游自动查找已装扩展配置的行为），并以 `AGENT567_BROWSER_TARGET` 记录设置入口的目标归属；不改变 MCP Schema。
  已有自定义路径/未知通道保持原样，除非用户明确选择新目标。未知默认应用要求手选，不回退 Chrome；找不到目标或启动失败不保存连接。
  默认应用识别是设置时的快照；保存后的目标保持稳定，不随用户更改系统默认浏览器自动迁移。
  官方扩展仍只有 Chrome 商店入口。Edge 默认提供内置包准备：随软件分发官方签名 CRX 0.4.0，锁定 SHA-256、验证发布者签名与 manifest 公钥 ID，保留 Apache-2.0/React MIT 许可。
  点击后解压至用户数据根 browser-extensions/playwright 下的版本与摘要目录（非缓存），只省略商店保留的 _metadata，扩展代码与 manifest 不改。
  打包时离线校验并包含资源，运行时不下载。已有目录只校验复用，损坏或用户修改的目录不覆盖；跨应用升级保持路径稳定。
  打开 edge://extensions/ 并保存同一目标的连接配置，用户仍需开启开发人员模式、加载解压目录和首次授权。主入口同时展开三步指南并显示可复制路径；准备不等于已安装或已连接。
  商店仍为备用选择。解压版不从商店自动更新，未来扩展升级使用新目录并由用户确认；不修改 profile、企业策略、注册表或系统安装目录。
  若准备或浏览器启动失败，不保存连接；保留高级草稿和其他 MCP 配置。
- 复用现有用户 MCP 配置和延迟工具发现，不增加自研 CDP 转发器或浏览器权限协议。
  普通文件 MCP 原本按工作区复用；扩展为有状态连接，Desktop 在合并项目覆盖后把这条连接交给已有 Session 专属 MCP supervisor，
  与动态插件贡献共存。共享 supervisor 不启动它，其他连接器仍复用。不增加配置字段或迁移；禁用/重配仍遵循在途 Turn lease 释放。
  启用后首次 MCP 启动通过托管环境的 npx 下载锁定组件；仅用于扩展，不安装或启动独立 Chrome。
- 首次由扩展批准连接并选择目标标签页。保留上游默认的每客户端标签组，任务不跟随用户后续切换的焦点。
  可选令牌跳过重复连接批准，不代表可以访问任意标签页；令牌按现有 MCP env 合同保存在本机配置，UI 不把它发到聊天或日志。
- Agent 可用且未禁用 browser-use Skill 时，系统提示明确网页交互、已登录页面及网页视觉/行为验证应主动调用该技能；
  公开事实仍优先搜索，解释功能与代码中出现 URL 不意味着需要浏览器访问。此为提示政策，不宣称能强制每个模型正确选路。
- Skill 优先发现已配置扩展的工具；验证首次快照的标题/URL，沿用同连接。拒绝、断线、缺扩展时说明原因，不能静默切换到另一浏览器。
  已配置 CDP、明确要求的独立窗口及插件 `ctx.browser` 继续保留原合同。扩展调用不要求先安装 CLI。
- 保存前重新读取并合并配置，仅改此连接的启停/配对字段及用户明确选择的浏览器目标；保留其他 MCP、既有命令选项、版本、授权与环境项。
  同名自定义命令或非扩展 Playwright 不覆盖，提示在能力页编辑。停用保留配对，不强制终止既有在途回合。

## 备选方案

- 自研 MV3 扩展与 CDP/Native Messaging 桥：可以深度定制，但需要自行维护调试器连接、跨平台安装、鉴权、标签身份及浏览器升级兼容；本次不重复已有上游能力。
- 仅修改 CLI auto-connect 提示：Chrome 144+ 可在 inspect 页面开启调试而免启动参数，但仍需要浏览器侧设置，也未提供用户期望的扩展入口。
- 默认给所有人启用扩展 MCP：会在没有安装扩展、没有提出网页任务时增加依赖准备和失败噪音，因此改为显式启用。

## 验证与边界

配置组件流程覆盖先绘制后加载、启用/重开/停用/重启用、错误重试、重名保护与保留其他配置；
Prompt 合同覆盖技能存在、缺失、禁用和不可调用。插件构建验证发布制品仍包含 Skill 与指引。
上游锁定版本的 CLI 启动与 MCP 初始化/工具清单可隔离验证，真实扩展安装、浏览器授权和选页需用户测试。
不读取或修改用户的真实浏览器 profile，不改历史、模型、线路、草稿或协议配置。
