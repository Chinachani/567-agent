# ADR-0127：将未审核 MCP 发现目录与可安装市场分开分发

- 状态：已接受
- 日期：2026-10-04

## 背景

官方能力市场把五万余条 MCP 候选和可安装 Skills 放在同一份清单与 GitHub ZIP 中。客户端对清单和压缩包都有体积上限，导致新目录无法同步，界面只能回退到旧缓存。候选条目也不应因为被采集就获得安装权限。

## 决策

1. 市场主分支 `main` 的 `marketplace.json` 仅发布可安装能力；Skills 与经维护者审核过安装配置的 MCP 仍由该分支归档分发。原有清单路径和 ZIP 安装合同继续兼容。
2. 未审核 MCP 候选单独发布到能力市场仓库的 `catalog` 分支。该分支包含 `index.json`、按分类、大小和数量分片的 MCP 记录、SHA-256 摘要，以及供维护者审核的分类建议。
3. `marketplaceVersion` 只随可安装清单变化；发现目录使用独立 `catalogVersion`。只有候选变化时，客户端不重新下载 Skills 和安装包归档。
4. 客户端只信任内置官方市场仓库的发现分支。它验证索引、分片大小、摘要、版本、记录数量和唯一 slug；候选固定映射为只读 MCP 条目，`installable: false`，不进入安装器的可安装清单。
5. 安装清单和发现目录独立同步：安装清单先激活，发现目录在后台逐批发布。索引先解析 `catalog` 分支的 commit SHA，随后索引和所有分片都从该 SHA 下载，避免工作流切换分支内容时混用版本。
6. `mcp-discovery-catalog.ts` 负责数据合同，`mcp-discovery-feed.ts` 负责有界下载、独立校验和按摘要缓存，`open-marketplace-service.ts` 负责与安装快照合并。每批最多四个请求；暂时性网络、超时和限流错误重试一次。失败分片不会移除已加载的有效项，后续刷新只补缺片。缓存校验失败时重新下载；只保留当前和上一代分片。
7. 单条数据不符合合同会被跳过并计入错误数，分片整体的字节长度、摘要、版本和原始记录数量仍必须匹配。兼容旧目录缺失的可选 `icon` 字段，默认空字符串。发现项固定显示“未审核 · 安全性未知”；分类与标签可来自自动浏览规则，维护者确认值优先，自动规则不推断权限或安装资格。
8. 页面先按范围和搜索计算可用类型，再按类型计算分类；已知分类别名使用同一规范键，未知分类不能仅因译名相同而合并。候选也参与搜索与分页；装饰图标最多显示 48 项，同名关联只保存前 32 个链接及真实总数，避免海量同名记录产生平方级内存占用。
9. 索引可选提供 `searchShards`：列表优先下载只有名称、短描述、分类、标签和 `detailShard` 定位的摘要分片。没有搜索分片的旧目录继续载入完整分片。详情通过只读 IPC 在用户打开抽屉后按需下载，校验仍以固定 revision、摘要和条目身份为准；失败保留摘要并允许重试，同一详情分片的并发请求共享一次下载。
10. 同步工作流对所有触发来源使用同一个并发组，保证 `main` 与 `catalog` 的状态更新串行。

## 备选方案

- 继续扩大单一 JSON 和 ZIP 上限：仍需下载和解析全部安装内容，无法区分发现与安装，也容易再次触及平台限制。
- 把所有 MCP 候选并入主清单：增大可安装清单、归档和校验成本，且容易把“已发现”误认为“已审核”。
- 逐条请求上游仓库详情：会产生大量 GitHub/API 请求，并受限流与上游格式变化影响。

## 影响与验证

- 仓库维护者可以扩展发现源、调整分类分片，而不重发 Skills 归档。
- 新客户端可展示完整 MCP 候选并使用分类筛选；未经审核项不会出现安装操作。
- 首次浏览优先下载搜索摘要，完整详情只在打开条目时下载；后续发现更新不触碰可安装归档。同步任务继续运行市场仓库的 Python 收集器测试。
- 已增加索引/分片合同、缺失图标、错误记录隔离、摘要校验、离线读取、失败重试与断点续传测试；市场服务测试覆盖安装清单先激活和发现项不进入安装器；页面流程测试覆盖刷新、类型/分类/搜索组合与安全标记。
- 采集端批次读取审核元数据，单条记录序列化一次来计算分片大小；测试使用中文内容验证 UTF-8 字节上限、摘要和回读合同。
- 首次完整浏览需下载全部搜索摘要；详情采用按需加载。搜索和分页在本地执行，不是服务端查询。容量合同仍需两端协调扩容，采集端在 80% 时告警、超限时中止暂存发布并保留上一版。分类准确性与翻译覆盖率需要持续维护。
- 两仓保留相同合同 fixture，分别经过生成端出口校验与客户端真实 Zod 解析。安装入口以已校验的包内容为准，不能信任发现条目的安装声明；GitHub 带 Token 的主清单采用 raw API 响应，兼容超过 1MiB 的文件。
