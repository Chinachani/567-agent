# ADR 0141: 上游远控、历史和消息顺序的本地适配

状态：2026-10-24 本地候选；未发布、未安装。

## 背景

历史核查范围为上次产品拉取的 main/dev 可达历史并集之后，到 openvetta/open-vetta `44260a2d29c5333b0b33e851376c11196453c213`。本次按用户授权采纳远控性能、长会话回传、模型参数和压缩队列改进，继续保留 567 的品牌、账号、线路、输入授权和聊天 UI。

## 决策

- 远控仍使用现有捕获母流、路线克隆、WebRTC 与输入授权。引入上游的 screen scale/stats/adaptation 算法，H.264 优先且保留其他编码回退，4 Mbps 起步提示、12 Mbps 上限、30 FPS 上限；按手机实际显示尺寸、缩放和持续编码压力调整发送尺寸，输出尺寸尽量保持偶数。参数更新串行且合并，采样失败不终止输入或捕获。主机拥有轨道释放，调参器只拥有参数和采样状态。
- 新主机在原有 DataChannel 能力消息中增加可选 `viewport:true`，新手机只有收到此能力才发送有界 viewport 反馈；旧端不接收新信令类型。viewport 独立校验与去重，不经过系统输入适配器，也不能启用输入；其序号独立于输入去重，避免布局协程抢先发送后丢失按键。桌面和 Android 使用相同的三个 STUN 地址；完整 RTCConfiguration 仍可由宿主覆盖。
- Android 已安装的 libwebrtc 144.7559.12 支持两处 field trials 设置，同时在 initialize 和 factory builder 应用零播放缓冲实验。没有复制上游强改 H.264 协商 profile 的做法，以免宣称支持未真实协商的编码参数。
- `session.history` 新请求可声明 `boundedPages:true`，响应增加可选 `nextOffset`/`hasMore`，按最终 UTF-8 JSON 字节数控制在 900000 以内并预留信封空间。新手机验证游标恰好按原始消息数递增，短页继续取；旧桌面没有游标时仍按条数分页。旧手机请求保持原页行数，避免提前停止。单条超大内容可截短并标记 `truncated:true`；新手机明确提示完整内容保留在电脑，桌面源历史不修改。
- 自定义模型拉取保留兼容的 ID 列表，并新增可选 modelDefinitions；解析明确的上下文、输出上限、视觉和推理档位，未知保持未知，不从型号名字猜测。真实密钥只在主进程从既有凭据库读取。设置页只给新增的选中模型保存参数，不覆盖手工配置；推理档位可重排，默认值按内容保持。
- 自动压缩的既有存储事件已带 turnId，本次使文档和历史投影保留该字段，并把它变为回复中的显示步骤。手动及旧记录继续使用原边界样式。宿主继续使用本地的每次模型调用回放合同，只额外保留本轮最近一次压缩步骤；回复结束清理。重放按回合与时间对账，避免重复步骤。
- 本地队列没有上游 conversation-feed 的全回合回放事实源，因此不复制其 queuedUsers 状态。重新进入仍在输出的已有会话时，先在已可见的页面壳后恢复规范历史与乐观消息，再接每次模型调用的实时回放；这类会话不再让迟到的历史回填把已执行队列的用户消息和回复挪到末尾。未运行会话仍沿用延后回填以保护首屏。
- Markdown 文件与网址复用一个 Radix 右键菜单展示合同，宿主注入可选复制/定位能力；文件打开仍走现有预览入口，网址打开仍走现有外链验证。无新增任意命令、编辑器发现或文件读取权限。只修复裸网址吞入外围 Markdown 结束符的情况，显式链接、代码和合法 URL 参数保持原义。

## 验证与限制

定向测试覆盖历史真实 RPC 分页与手机游标、模型拉取/选择/保存/回读、压缩事件与持久历史、运行会话重进、队列发送、链接识别及右键操作。隔离 Chromium E2E 验证实际尺寸变化、移动像素和输入回传；隔离 Electron 布局探针检查深浅主题及窄侧栏。具体命令与结果见本轮修补记录。

零播放缓冲可能增加弱网抖动；WebRTC 仍自行拥塞控制。STUN 不等于 TURN，不能保证所有 NAT 可直连。未执行用户设备操作或真实 Windows 安装矩阵；这些结果不替代真机体验验收。
