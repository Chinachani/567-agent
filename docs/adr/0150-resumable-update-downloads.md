# ADR-0150：可恢复的应用内更新下载

状态：已实现
日期：2026-10-31

## 背景与备选

手机更新原本打开浏览器，无法在应用中查看进度或恢复下载。电脑使用 electron-updater，但它的完整安装包传输不是多连接下载，GitHub provider 也明确关闭 multipart Range。重写整套更新器会扩大到平台安装、验签和差分合同；引入外置下载进程还增加分发和生命周期成本。Android DownloadManager 提供后台传输，但没有可控的分段并发策略。

## 决定

- Desktop 只替换 electron-updater 的完整文件传输方法，最多四条单范围 HTTP 请求；差分、发布源、SHA 校验、平台签名、缓存与安装准备继续由原更新器管理。下载由 Electron 专用网络 Session 发起，沿用系统网络代理；不把账户会话送入下载请求。依赖的窄内部接口由合同测试保护。
- 下载片段按 URL 与摘要隔离保存，不依赖临时安装文件。取消或退出保留片段；重新开始相同包时续传。不支持范围请求时单连接下载，始终验证整体摘要；内容错误不能成为可安装结果。有限重试不修改下载源。
- Android 用应用私有目录、独立前台服务和最多两连接，界面与通知显示下载状态，可暂停和继续。重启进程恢复为暂停；不会自主下载或安装。前台服务按 Android 的 dataSync 限制运行，系统终止后可手动恢复。
- APK 大小与 SHA-256 取自官方 GitHub Release 元数据；既有镜像只代理包传输。安装前验证摘要、当前包名、版本递增与当前签名。安装源授权与安装本身由系统及用户确认。签名轮换暂保守拒绝，需手动检查后安装；测试版不下载不兼容的正式 APK。

## 兼容与后果

不更改聊天、账号、线路或自定义模型协议。缺少官方摘要的旧发布保留打开发布页；不从不可信镜像补造摘要。分片可能占用额外磁盘空间，多连接不保证任何网络上的固定提速。Desktop 更新器依赖升级时需复核 executor 接线；Android 后台服务不能保证在用户强制停止应用后继续。

## 验证

本地 HTTP 与文件系统流程覆盖并发分片、暂停后重新创建下载器续传、忽略范围、错误范围与损坏内容拒绝；覆盖服务/IPC/preload与真实UI状态操作。平台安装与打包边界由候选CI、打包E2E和发布校验继续验证，不使用真实付费模型或用户应用状态。
