# ADR-0162: 专家使用普通会话，团队新任务统一到项目协作

- 状态：源码已实现，尚未完成行为与实机验证
- 日期：2026-11-15

## 背景

Desktop 同时提供 Agent Team 专用协调会话和项目内普通会话协作。两套新建入口要求用户先理解运行机制，预设智能体又只能先打开档案，无法直接开始。用户要求用现有协作替代旧团队，并提供带流程的内置专家。

## 决策

1. `/agents` 提供专家、会话协作两个入口。专家直接进入已有 `agent:<profileId>` 普通新会话草稿，只有用户发送目标后才创建 Runtime 和调用模型。
2. 专家仍由插件声明式提供。首批沿用主控、开发、研究、审阅和方案五个稳定身份，提示词中包含输入、步骤、交付要求和边界。提示词与流程共用同一 Markdown 事实源，不引入第二套工作流执行引擎或扩大插件 manifest 合同。
3. 复制专家先形成可编辑草稿，保存时原子创建完整档案。副本保存当时的有效提示词、能力选择及来源身份；不修改插件维护的原件，不在两次持久化之间留下半成品。
4. 新多人任务进入项目详情的现有会话协作：选择同项目会话、设置职责和读写权限，再由现有协调工具调度。专家会话是普通会话，可直接加入该协作。
5. 旧 Team 不再创建新团队、新会话或接收新消息。根据用户追加要求，移除旧团队工作页、设置抽屉和中心的历史标签。历史侧栏入口与会话/成员深链转到普通只读会话查看器，查看器保留停止旧任务的操作；旧列表、设置、新建链接导向会话协作。历史存储、档案、模型偏好及底层读取/终止合同保留，不能因撤下页面而清理数据或删除插件声明。
6. 不自动把历史协调会话转换为普通会话，也不自动复制成员创建新 Runtime。旧任务的执行状态和上下文不等价于普通会话协作任务，静默转换会丢失语义。
7. 编辑草稿保留打开时的档案与版本号。插件刷新不覆盖本地编辑；保存时仍使用起点版本校验，拒绝覆盖较新的存储。复制草稿在来源被移除时保留，主进程在保存时明确拒绝已失效的来源。
8. 专家目录按已知稳定身份分为规划、开发、研究、审阅和方案，沿用相同模板的副本保留专业分类；其他本地档案归入自定义，其他插件档案归入扩展专家。不从名称或提示词猜分类，不改变插件公共合同。专家按名称/说明/流程搜索，并以 12 项分页；协作项目按名称/路径搜索，同样以 12 项分页。
9. 项目协作候选会话与任务记录分别搜索、以 8 项分页；过滤只影响显示，不裁剪成员草稿和任务全集。关键词或分类改变回到第一页，数据变少夹紧页码，切换项目重置搜索和翻页。暂停、停止、协调成员选择仍使用完整数据。

## 备选方案

- 只更名旧团队入口：仍存在两个执行机制，不能满足替代目标。
- 删除 Team 清单或存储：会触发预设删除及成员裁剪，破坏历史引用。
- 新建专家引擎和流程 Schema：当前需要是可复用提示词与步骤，现有档案绑定已可承载，无需新增公共协议。

## 后果与边界

旧执行核心暂时仅承担历史读取和在途任务收尾，待明确历史存档格式后再移除；不能删除历史所需模块。专家的流程属于模型指引，不是强制审批状态机，不能扩大工具权限或绕过现有确认。现有项目协作配置和手机协议均保持原样。

专家目录沿用新会话页的共享缓存，同时订阅插件和本地档案变更；旧请求不能覆盖刷新后的结果。旧团队深链解析在页面绘制后进行，使用只读存档快照，不恢复成员 Runtime 或重新调度排队任务；失败时提示存档保留并提供重试和协作出口，不挂载旧团队工作页。无法解析为普通会话路径的古老存档仍保留原文件，当前查看器不负责转换它们。

预设市场沿用已有 GitHub 能力来源和插件安装器；本次仅补充新仓库方案，不新增市场类型或远端来源。专家包依旧需要有效插件入口和 Module Federation 清单，安装启用后声明式贡献档案。市场分类与专家目录分类为两种展示合同，不能假设任意市场分类会自动写入专家档案。见 [预设市场仓库指南](../expert-preset-marketplace.md)。

本批更新了受影响的既有合同与历史展示用例，未新增或运行行为测试，也未启动真实客户端。当前完成状态仅表示源码落地和静态检查，不代表完整 1.6 版本已验收。
